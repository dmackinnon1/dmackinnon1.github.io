# chessdom

Interactive mathematical chess puzzles, in two families:

- **Placement puzzles**, about *domination* (*covering*) and *independence* (*unguarding*):
  where to put pieces so they attack every square, or so that none attacks another.
- **Tour puzzles**, about paths a piece takes when it visits every square of the board once.

Try them out at [dmackinnon1.github.io/chessdom](https://dmackinnon1.github.io/chessdom/).

| Page | What it is |
|---|---|
| [Puzzles](https://dmackinnon1.github.io/chessdom/puzzles.html) | Classic domination and independence puzzles, e.g. eight independent queens. |
| [Explorer](https://dmackinnon1.github.io/chessdom/) | Place pieces on boards of different sizes and see what they cover. |
| [Piece Meal](https://dmackinnon1.github.io/chessdom/capture.html) | Capture pieces with each other until one is left (inspired by the NYT "Capture" puzzle). |
| [Safe Harbour](https://dmackinnon1.github.io/chessdom/avoidance.html) | Place one piece in each coloured region so that no piece attacks another. |
| [Kixote](https://dmackinnon1.github.io/chessdom/kixote.html) | Retrace a knight's tour from some of its numbers. |
| [Hidato](https://dmackinnon1.github.io/chessdom/hidato.html) | Retrace a king's tour. |
| [Numbrix](https://dmackinnon1.github.io/chessdom/numbrix.html) | Retrace a tour that moves one square up, down, left or right. |
| [Tourist](https://dmackinnon1.github.io/chessdom/tourist.html) | Build your own tour, with optional counts and hints. |
| [Joust](https://dmackinnon1.github.io/chessdom/joust.html) | Outlast an adversary: neither of you may land where either has been. |
| [Generator](https://dmackinnon1.github.io/chessdom/generator.html) | See how hiding numbers on a tour lets other paths fit. |

The pages are plain HTML and JavaScript with no build step, and use Bootstrap 3's
stylesheet for layout and the chess piece icons.

## Placement puzzles

In the mathematical chess problem of domination, you are tasked with finding an arrangement of
several pieces of the same type so that every square on the board is reachable in a single move by
at least one of the pieces. In the problem of independence, your goal is to place the maximum number
of pieces of the same type so that none of the pieces lie in the path of another.

On the [Explorer](https://dmackinnon1.github.io/chessdom/) page, you can experiment by placing pieces
on boards of different sizes. When using this page, you are not restricted to use only pieces of the same type.

![explorer example](https://raw.githubusercontent.com/dmackinnon1/chessdom/master/imgs/explorer_example.png)

On the [Puzzles](https://dmackinnon1.github.io/chessdom/puzzles.html) page, you can attempt to solve a
number of mathematical chess puzzles involving domination and independence. For example:

![puzzle example](https://raw.githubusercontent.com/dmackinnon1/chessdom/master/imgs/example_puzzle.png)

Information on mathematical chess puzzles can be obtained from many sources online. My primary source
was John J. Watkins' book *Across the Board* (2004, Princeton University Press).

Puzzle definitions are stored in **data/puzzles.json**, one puzzle per line, and can be edited directly.
(The file was originally generated by the **build/puzzles.py** script.) Each puzzle has this format:

```javascript
{
  "name": "8 queens on 8x8",
  "size": 8,
  "cover": true,
  "unguard": true,
  "pieces": [
    {
      "name": "queen",
      "count": 8
    }
  ]
}
```

The puzzle above is the classic "8 queens" problem, one of the more difficult problems in the set.

## Tour puzzles

These came from the [kixote](https://github.com/dmackinnon1/kixote) project (2016–2026), whose
history is now part of this repository.

A *path puzzle* is built from a numbering of the squares on a chess board. The numbering follows a
path taken by a particular type of chess piece as it moves over the whole board, landing on each
square exactly once (a *tour*). Once all the squares are numbered, some of the numbers are hidden,
and the solver's task is to fill them in, rediscovering the original path. In the interactive versions
here the squares are filled in order: you can look ahead, but each turn you can only fill in the next
number in the sequence.

- **Kixote** puzzles follow a knight's tour,
- **Hidato** puzzles follow a king's tour,
- **Numbrix** puzzles follow a tour by a *wazir* (the fairy chess name for a piece that moves one
  square up, down, left or right).

Puzzles are made the same way for all three types:

1. Choose a random starting square.
2. Build a tour with *Warnsdorff's rule*: always move to the square with the fewest free moves onward.
   This doesn't always cover the board, so it may take more than one attempt.
3. Hide numbers, following a rule for each puzzle type that was arrived at by experiment.
4. Find every way to fill in the hidden numbers. If there is more than one, reveal a square where
   the solutions differ, and repeat until only one solution is left.

The [Generator](https://dmackinnon1.github.io/chessdom/generator.html) page lets you explore step 4
by hand, and [Tourist](https://dmackinnon1.github.io/chessdom/tourist.html) lets you try Warnsdorff's
rule yourself.

## Code

Each page loads a few shared scripts from `js/` and one script for its game.

| File | What's in it |
|---|---|
| `chess_base.js` | The board, its squares, how each piece moves (`MOVES`), pieces, and shared page helpers. |
| `bldrs.js`, `evnts.js` | A small HTML/SVG builder, and a simple event system. |
| `menu.js` | The menu at the top of every page (add a page here and it appears everywhere). |
| `tour.js` | Tours, Warnsdorff's rule, the path-puzzle solver, and tour maps. |
| `chess_domination.js` | Explorer and Puzzles. |
| `capture.js` | Piece Meal. |
| `avoidance.js` | Safe Harbour. |
| `tour_puzzles.js` | Kixote, Hidato and Numbrix. |
| `tourist.js`, `joust.js`, `tour_generator.js` | Tourist, Joust and the Generator. |

Every game follows the same pattern: a class holds the game's state and rules and knows nothing about
the page; whenever something changes it fires a `gameChanged` event, and display functions at the
bottom of the same file draw the page from the game's state.

## Tests and research

- `tests/tour_equivalence.js` checks that the shared tour code behaves exactly like kixote's original
  code (kept in `tests/kixote_original/`). Run `node tests/tour_equivalence.js`; it needs only Node.js.
- `research/` holds a study of Piece Meal's difficulty: how the levels were chosen, and why knight
  puzzles are the hardest. See `research/README.md`.

## Publishing

The live site is published from the [dmackinnon1.github.io](https://github.com/dmackinnon1/dmackinnon1.github.io)
repository: copy this repository's pages, `css/`, `js/`, `data/` and `imgs/` into its `chessdom/` folder.

The tour puzzles used to live at `dmackinnon1.github.io/kixote/`. The pages in `publish/kixote/`
forward those old addresses to the new ones; see `publish/kixote/README.md`.
